SpeakoFlow uses your GPU when it can and falls back to the CPU otherwise. You don't normally need to touch this — the defaults pick the best available device on every platform.

The controls live under *Settings → General → Experimental*, so you have to turn **Experimental features** on to see them. That's deliberate: choosing a backend by hand is a diagnostic tool, not a tuning knob.

| Platform | GPU backend used |
| --- | --- |
| macOS | Metal |
| Windows | Vulkan (and DirectML for ONNX models) |
| Linux | Vulkan, with OpenBLAS for CPU math |

## Whisper acceleration

*Auto, a specific GPU, or CPU. Default: Auto.*

One dropdown covers both the backend choice and the device choice. It lists **Auto**, then every compute device SpeakoFlow detected with its reported memory (for example `NVIDIA GeForce RTX 4070 (12.0 GB)`), then **CPU**.

- **Auto** (default) — use the best available GPU, falling back to the CPU when there isn't one. On multi-GPU machines a dedicated GPU always wins over an integrated one, even when the integrated one reports a larger shared-memory budget.
- **A specific device** — pin inference to that GPU. Useful when you want transcription off the GPU your game or render job is using.
- **CPU** — force strict CPU inference. Slower, but it sidesteps every driver problem.

This setting drives both transcription engines. For the current ggml/GGUF engine, Auto and a specific GPU both resolve to "automatic backend with a guaranteed CPU fallback", so neither can leave you unable to transcribe on a machine with no usable GPU.

## ONNX acceleration

*Auto, CPU, CUDA, DirectML, ROCm. Default: Auto.*

This applies only to the older-engine models that run on ONNX Runtime — Parakeet, Canary, Moonshine, SenseVoice, GigaAM, and Cohere. The dropdown is hidden entirely unless your build has more than one option compiled in, so most Linux and macOS users never see it.

**On Windows, Auto resolves to DirectML** when DirectML is compiled in, which it is in the official build. This is not what the underlying library does by default: its own "Auto" deliberately skips DirectML, which would silently pin every ONNX model to the CPU and make Parakeet feel inexplicably slow. SpeakoFlow overrides that. CPU remains the final fallback, so a machine without a DirectX 12 capable GPU still works.

On macOS and Linux the official builds compile no ONNX GPU provider at all, so ONNX models run on the CPU there regardless of this setting.

## Checking what your machine can actually use

Run the app from a terminal with `--list-devices`. It initializes the native engine, prints every compute device it can see with its memory, prints which backends (Vulkan, Metal, CPU) are actually available at runtime, and exits without opening a window. That distinguishes "my GPU isn't detected" from "the app is choosing not to use it".

## Why Linux enumerates GPUs in a separate process

<Warning>
  On Linux only, SpeakoFlow enumerates compute devices by launching a short-lived copy of itself rather than doing it in-process. Windows and macOS keep the direct in-process call.
</Warning>

The reason is worth stating plainly. The vendored, statically linked whisper.cpp/ggml is compiled with ggml's default `-march=native`, meaning it targets the exact instruction set of the machine that built it. On Linux, packages are routinely built on one machine and run on another, so loading ggml's Vulkan backend on a CPU narrower than the build machine's can raise `SIGILL` — an illegal-instruction crash that cannot be caught and would take the whole app down at launch.

Running the probe in a child process turns that from "the app won't start" into "no GPU is listed". If the child crashes, hangs (it's killed after 30 seconds), or produces nothing parsable, SpeakoFlow logs a warning and carries on with CPU transcription.

There's a second, related guard on every platform: if your x86-64 CPU lacks FMA3 support (some older Xeons, for example), GPU enumeration is skipped outright, because ggml's Vulkan backend uses FMA3 internally and GPU acceleration wouldn't work there anyway.
