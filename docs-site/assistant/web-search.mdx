Optional. When a question needs current, factual information, the assistant can look it up. The model decides when to search — you don't have to ask.

Enable it in *Settings → Assistant → Web search*. Off until you turn it on.

## Allow web search

*Default: off.*

Lets the assistant search the web when a question needs current information. Everything below only appears once this is on.

## How it decides to search

The model decides, by calling tools while it writes its reply. There is no keyword check and no separate planner to configure. Turning web search on gives the model two tools:

- **`web_search(query, freshness, news)`** — runs a live search and hands back titles and short snippets. The model writes the query itself, and can ask for a freshness window (`day`, `week`, `month`, `year`, or none) and flag the topic as news.
- **`get_current_datetime()`** — your current local date and time, with a UTC offset. Models have no clock, so this is how "what's today's date" and "how long until X" stay correct, and how a relative phrase becomes a concrete date before a search query is built.

A turn runs at most three model rounds, so the assistant can search, read what came back, and search once more before it has to answer with what it has.

Each search is a single retrieval pass that returns titles and snippets. Result pages are never fetched, so a search costs about a second rather than a browsing delay. If a search fails or returns nothing, the assistant answers without web context instead of leaving you waiting, and the panel shows a short "no web results" notice.

<Note>
  The system prompt also tells the model not to claim it can't access the internet. Without that, a model would confidently refuse on the turns where it decided not to search — the worst possible answer when the tool was right there.
</Note>

## Two ways to search

### Use OpenRouter's built-in search

*Default: on. Only shown when your assistant provider is OpenRouter.*

Lets OpenRouter run the search itself — its `:online` mode — billed to your OpenRouter credits, with **no separate search API key needed**. This is the one provider with native search, so it's the one exception to the tool path; every other provider, cloud or local, searches through the tools above.

Turn it off to use your own search provider instead. It also steps aside automatically on a turn that carries an image, since OpenRouter's server-side search can't be paired with an inline screenshot — those turns use the tool path like everyone else.

### Search provider

*Serper, Brave, Tavily, Exa, SerpAPI, TinyFish. Default: Serper.*

All six return titles and snippets, and each needs one API key. Every one has a free tier.

| Provider | What you get |
| --- | --- |
| **Serper** | Google results, fast (~1–2 s). The default. |
| **Brave Search** | An independent index. |
| **Tavily** | AI-oriented search; returns a synthesized answer alongside results. |
| **Exa** | Neural, semantic search. |
| **SerpAPI** | Google SERP. |
| **TinyFish** | Its own index, built for agents. Free with no credit card. |

<Tip>
  Serper stays the default because it's fast and its free tier is generous. TinyFish asks for no payment details at all, if you'd rather not hand over a card just to try search out.
</Tip>

### API key

Key for the selected search provider, stored in your OS keychain. Each provider keeps its own key, so switching providers doesn't wipe the one you already entered. Not needed when you're using OpenRouter's built-in search.

### Test search

Runs a sample search with the current provider and key and reports how many results came back, so you find a bad key here rather than mid-conversation.

## Search depth

*Quick, Standard, Deep. Default: Standard.*

The single dial for how thorough a search is. It sets how many of the model's queries actually run, how many results come back per query, how many sources reach the model, and how much of that text fits in the prompt.

- **Quick** — one query, 5 sources, a small context budget. Simple facts.
- **Standard** (default) — up to 3 queries, 8 sources. The right answer for most questions.
- **Deep** — up to 4 queries, 10 sources, the largest context budget. Hard or multi-part questions.

All three tiers are one retrieval pass with heavy parallelism and tight timeouts. This is "answer with search in a couple of seconds", not minutes-long deep research. Results from multiple queries are merged round-robin, de-duplicated by URL, and reranked locally on keyword overlap plus a recency boost for news — no extra model call.

## Smart search decisions (local model)

*Shown only when your assistant brain is the built-in local model. Currently has no effect.*

This toggle predates model-decided search: it used to pick between an LLM planner and a fast keyword check for the built-in model. Now that the built-in engine calls the `web_search` tool like every other provider, nothing reads the setting. It's still in the interface, but changing it won't change behavior.
